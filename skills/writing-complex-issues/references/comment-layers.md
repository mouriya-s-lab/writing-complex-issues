# comment 修订层

什么时候读我：为既有 thread 补齐决策、架构切片、log 义务，或落设计修正时。

**body 一经发布不再改写，后续内容以 append-only comment 分层补齐。**理由：body 是已被 children/PR 引用的锚，原地改写让既有引用静默指向新语义；comment 层保留修订历史，headless 读者按时间序 reconcile 一次即可（配合设计修正层的显式收回，reconcile 成本是有界的）。完整 thread = body + 以下各层；某层无内容也显式写（「无新事件义务」防画蛇添足）。

## 决策 comment

回答「body 留白处怎么定」。格式：「body 某处的『归 PR 定』收回，裁决为 X，依据 Y」。全树决策表 + 交叉自洽检查落 umbrella 的 master record，child 引用并复述影响自己的部分。裁决流程见 decision-closure.md。

## 架构切片 comment

回答四个问题，一个不许省：

1. **系统定位**：这是系统结构模型里的哪个部件。**用该系统自己的结构词汇回答**——状态机系统答词表定义/边准入/投影/引擎转移，流水线答哪一级及级间合同，分层系统答哪一层与层间契约，并发系统答哪个执行单元与共享点，数据系统答哪个模型与所有权，协议/API 系统答哪个面与版本边界。两个失败模式：把一切系统都套成上一个案例的模型（惯性替代了观察），和用框架名代替部件名（把结构问题让渡给工具）。
2. **全局坐标**：在哪条域边界上（值从哪个域到哪个域、信任级如何变化、parse/校验点在哪）。
3. **领域模型与值的一致性**：这条边界防哪类归属或漂移错误——例如一个域重定义别的域拥有的词表/形状、值不经 parse 跨域、同一值多域副本失同步。按实际语言和项目模型说明；存在编译期类型时，说明类型与运行时值如何保持一致。
4. **受控的错误类别与保证边界**：完成后防住哪类错误、靠什么实际机制、保证覆盖哪些路径、如何用真实路径验证。语言与项目模型支持时，优先用 ADT、受限构造和编译器穷尽检查让非法状态不可表达；对依靠边界解析、运行时校验或协议约束防住的错误，写清拒绝或处理行为及其证据，不宣称编译期消除了它。

切片的锚是 umbrella body 的「系统定位（全局结构图）」区块：模型在父层选定，切片只回答「我在选定模型的哪个位置」，不自行另选模型——发现父层模型容不下本 child 时，那是对父层的修正信号（走设计修正 comment 重选模型），不是切片即兴换模型的许可。架构不是框架选型——是结构模型 + 域归属 + 边界；绝大多数错误来自边界考虑模糊。

## log/观测义务 comment

回答「需要什么观测、为什么、现有能力是否足够；确需新增时，落在哪里、哪种 kind」。每个实现 issue 必答；义务总表落 umbrella。已有日志、指标、追踪或查询面足以支撑本 child 的结果与验收时，引用并复用，明确无需新增，不为填写模板扩建观测体系。

只有核实到缺失能力确实影响 child 的结果或验收，且需要设计裁决时，才单独立观测 RFC。RFC 的 Blocks 必须逐个点名这些依赖 children，写清各自缺少什么能力、为何现有观测不足、什么后置条件解除阻塞；不因“体系缺失或混乱”自动阻塞全树或扩大实现范围。无此依赖的 children 继续推进。repo 不可达时登记为 c 类未知，交由 audit child 核实具体能力及受影响范围；事实未明不当成全树缺陷，也不把尚无证据的观测能力当作已具备。

该 RFC 按实际缺口裁决受影响的**受众原则**（谁消费、为何需要相应结构）、**分域模型**（业务与运维观测的归属、受控跨域摘录边界）、**事件分类**（kind 词表归谁、完整处理由什么机制保证）和**查询面**（消费者如何取得所需证据，复用已有合适入口）。不受本次缺口影响的部分引用现行契约，不重新设计。事件模型支持时优先使用编译器穷尽检查；否则说明项目实际采用的解析、校验或协议保证及真实验证路径，不把某一种类型系统能力当作通用前提。

## 设计修正 comment

操作员镜头修正或审查发现触发。格式：「收回 X，改为 Y」+ 对 body 各节的影响逐节列出。被修正的旧表述显式收回——新旧并存等于把 reconcile 成本转嫁给每个未来读者。涉及登记表/范围的更正遵守稳定编号纪律（见 child-body.md 的 audit child）。
